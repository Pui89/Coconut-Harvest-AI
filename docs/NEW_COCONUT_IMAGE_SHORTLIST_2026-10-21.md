## Recommended order

- **For README context:** inspect candidate 1 first, then candidate 5 for a Thailand-related plantation scene. Use only if they improve the page over existing diagrams.
- **For a potential detection example:** inspect candidate 2 at full resolution; dense, distinct fruit instances matter more than image resolution alone.
- **For fruit appearance only:** candidate 4 is a close-up, not an orchard detection benchmark.
- Candidate 3 remains pending visual inspection; the licence is permissive, but usefulness for coconut detection is not yet established.

## Fast review workflow

1. Download the original only after confirming the current source page and licence; record source URL, creator, exact licence URL, retrieval date, dimensions, file type and SHA-256.
2. Inspect the original at full resolution for relevance, sharpness, lighting, occlusion and visible individual fruit boundaries.
3. Reject blurry, tiny, heavily occluded, redundant or irrelevant images.
4. For annotation, label only clearly separable fruit instances, create an overlay, validate box geometry and obtain independent review.
5. Compare file hashes and group related views by source/capture before splitting. Never place near-duplicate views across train and test.
6. Keep candidates pending until rights, annotation QA, duplicate checks and split assignment are independently recorded. A source-page licence is not proof that an image is training-ready.
